# Running the AI-powered Roast Bot (Grok backend)

## What this is
The frontend (`roaster.html`) tries to call a local backend server for a
real, live AI-generated roast using Grok. If the backend isn't running
or the request fails for any reason, it automatically falls back to the
original rule-based roast engine, so the demo never breaks even if
something goes wrong with the AI call.

## One-time setup

1. Get a Grok API key at https://console.x.ai (needs an xAI account)

2. Install backend dependencies:
   ```
   cd backend
   pip install -r requirements.txt
   ```

3. Set your API key as an environment variable (do NOT hardcode it in any file):

   macOS/Linux:
   ```
   export XAI_API_KEY="your-key-here"
   ```

   Windows (PowerShell):
   ```
   $env:XAI_API_KEY="your-key-here"
   ```

## Running it before the demo

1. Start the backend (leave this terminal running):
   ```
   cd backend
   python server.py
   ```
   You should see it start on `http://localhost:5000`. Check it worked:
   ```
   curl http://localhost:5000/health
   ```
   Should return `"api_key_configured": true`.

2. Open `roaster.html` in your browser (just double-click it, or drag it
   into a browser tab). The chatbot will now call Grok for real
   AI-generated roasts.

## Important for pitch night

- **Start the backend BEFORE you open the HTML file**, and before you go
  on stage. Test the full flow once beforehand.
- If the venue wifi is bad or Grok's API is slow/down, the app will
  silently fall back to the rule-based roast, it will still work, just
  without live AI generation. This is intentional so your demo can't
  fully break on stage.
- The backend must keep running the entire time you're demoing, don't
  close that terminal.
- Never commit your API key to GitHub or paste it anywhere public.

## What changed vs the rule-based version

- The roast text itself can now be freshly generated by Grok instead of
  picked from a fixed list of templates.
- The AI is instructed (via a system prompt) to only use the real
  category and amount data you give it, and never invent numbers, but
  since it's a live model, there's inherently more risk of it drifting
  from that than the old fully-deterministic version. If this comes up
  in Q&A, that's an honest tradeoff worth naming out loud.
